## 2026-08-30 - Require a seat token on every mutating Yatzy endpoint, remove client-triggered bulk purge

Decision: Deleted `api/yatsy/games/purge.js` and made seat-token proof mandatory on the two remaining unauthenticated mutating paths: `DELETE /api/yatsy/games/[code]` now requires a matching `role` + `resumeToken`, and `POST /api/yatsy/games/[code]/join` on a room whose status is already `playing` requires the caller to present the token for the seat they are reclaiming instead of being handed a fresh one. Added a 64 KB type-and-size guard on the `gameState` accepted by `PUT .../state`, and replaced the `innerHTML` template in `buildWinnerBanner` with `textContent` DOM nodes.
Context: A security audit requested by the user found that any anonymous caller could (a) wipe every row of `yatzy_games` with a single `POST /purge {"olderThanMs":1}`, (b) delete any room knowing only its 3-letter code, and (c) take over a seat in a game in progress, rotating the sitting player's token and kicking them out. Room codes are 3 letters (17,576 combinations), so the "capability" gating these endpoints was enumerable in seconds. The user chose to fix security first, to keep codes at 3 letters, and to preserve resume-by-code while requiring the token.
Rationale: `purge` was pure redundancy - the hourly `pg_cron` job in `0001_yatzy.sql` already hard-deletes rooms older than 48h - so deleting it removes an entire attack surface at zero functional cost, which beats authenticating it. For `join`, the legitimate "I closed my tab and came back" case was already served by `POST /resume` with the token persisted in `localStorage`; the client now forwards those same credentials when joining a code it already holds, so the user-facing flow is unchanged while anonymous seat takeover is gone. Deriving `localPlayerIndex` from the authenticated role (`creator` = 0, `joiner` = 1) also fixes a latent bug: the removed code assigned the seat of whoever's turn it was, contradicting its own comment claiming it replaced the inactive seat.
Consequences: `POST /join` on a room already `playing` now answers `409 game-in-progress` unless valid credentials are supplied - the `game-in-progress` error code and its FR/EN/ES copy already existed in `i18n.js` and `setSplashError`, so no translation work was needed. A player who loses their `localStorage` (cleared storage, different device) can no longer re-enter a game in progress at all; previously they could, by taking over a seat. `YATZY_MATCHMAKING.PURGE_AFTER_MS` and `YATZY_CONFIG.matchmaking.purgeAfterHours` are gone. `sw.js` `CACHE_NAME` was bumped to `yatzy-offline-v13`, without which returning players would keep running the cached pre-fix client. `GET /api/yatsy/games/[code]` remains unauthenticated and still exposes room state to anyone knowing the code - read-only, left open deliberately, logged as an Open_Question rather than changed outside the agreed scope.
Alternatives_Rejected: Keeping `purge` behind a shared secret or a Vercel cron header - rejected as redundant with `pg_cron`; less code beats more config. Lengthening room codes to 4-5 letters to make enumeration impractical - explicitly declined by the user for now, since codes are typed by players and rate limiting is the planned mitigation. Closing `join` on `playing` rooms outright (no reclaim at all) - rejected by the user, who wanted resume-by-code preserved. Full schema validation of `gameState` - rejected as premature: a type-and-size guard removes the storage-abuse risk without hardcoding the Yatzy state shape in the API, and rendering is now escaped at the sink anyway.

## 2026-08-30 - Add security headers, throttle public endpoints, swap the stored admin password for a signed token

Decision: Added `vercel.json` carrying security headers (global `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options: SAMEORIGIN`, `Permissions-Policy`; `Cache-Control: no-store` on `/api/*`; a strict Content-Security-Policy on `/admin` only). Split admin auth into a new `POST /api/admin/login` that verifies the password with `crypto.timingSafeEqual` and returns a 1h HMAC-signed token; `POST /api/admin/stats` now accepts only that token. Added `api/_lib/rateLimit.js`, an in-memory throttle applied to login (10 attempts / 10 min / IP) and to `/api/track` (60 events / min / IP). Added `ADMIN_PASSWORD` to `.env.example`.
Context: Audit priority 2 (see the audit action plan in `docs/BACKLOG.md`). The project had no `vercel.json` at all, so zero security headers; the admin password was brute-forceable without limit, compared with `!==`, and stored in plaintext in `sessionStorage` where any XSS could read it; `/api/track` was an unbounded write path into the Supabase project shared with coinchapp. The user confirmed traffic is currently very low.
Rationale: The token is signed with `ADMIN_PASSWORD` itself as the HMAC key and carries its own expiry, so verification stays stateless - no session table, nothing to keep in sync - and rotating the password automatically invalidates live sessions. The throttle is deliberately in-memory rather than Redis/Upstash: at very low traffic, a shared store would mean a new vendor and a new bill to defend a hub of party games, whereas per-instance counters already make a brute-force burst expensive. CSP was scoped to `/admin` rather than applied site-wide because the games pull from `esm.sh`, Google Fonts and Supabase over websockets, so a global policy needs per-game verification; `/admin` is small, fully controlled, and was verified under the real policy (fonts, inline style attribute for the ranking bar, same-origin fetch, module execution).
Consequences: `ADMIN_PASSWORD` must now be treated as a signing key, not just a password: changing it logs the admin out. Admin sessions expire after 1h. `X-Frame-Options` is `SAMEORIGIN`, not `DENY`, because `public/games/cafards/index.html` displays its rules in a same-origin iframe - `DENY` would break that modal. The throttle resets on serverless cold start and is not shared across concurrent instances, so it is a cost-raiser, not a guarantee. `/api/*` responses are now `no-store`, which also removes the risk of the Yatzy service worker caching a game-state read.
Alternatives_Rejected: Upstash Redis / Vercel KV for a correct distributed rate limit - rejected as disproportionate at current traffic, and it introduces a paid dependency; noted as the upgrade path if abuse appears. A site-wide CSP - deferred, it needs each of the 10 games verified individually. Vercel's built-in Password Protection - still paid-plan only. An httpOnly session cookie instead of a token in `sessionStorage` - rejected for now as it needs CSRF handling that a token in a request body does not, for the same practical protection on a single-user page.

## 2026-08-30 - Minimal serverless observability: redact 5xx detail, log it, guard every handler

Decision: Made `sendError` in `api/_lib/http.js` the single choke point for server errors: any status >= 500 now logs a one-line JSON record (`{level, code, detail}`) to stderr and returns a fixed generic message to the client, while 4xx messages still pass through untouched. Added `withErrorHandling(handler)` in the same file and wrapped all 8 serverless handlers with it. `readJsonBody` now returns `{}` on unparseable JSON instead of throwing. No client-side error reporting was added.
Context: Audit priority 3. `api/*` had no logging whatsoever, so a production 500 left no trace; raw Supabase messages (table and constraint names) were forwarded straight to the browser; and any throw - a malformed `sendBeacon` body hitting `JSON.parse`, or `getServiceClient()` with a missing env var - became an opaque Vercel `FUNCTION_INVOCATION_FAILED` with nothing logged. The user asked explicitly for the minimum.
Rationale: Routing everything through the existing `sendError` fixes the leak and the silence in one place, with zero changes at the ~30 call sites that already write `sendError(res, "server-error", error.message)` - the detail simply moves from the response to the log. No correlation id is generated because Vercel already tags each log line with the invocation, path and request id, so building one would be duplicated effort. Logging is `console.error` to stderr, which Vercel captures natively: no vendor, no dependency, no bill.
Consequences: Clients can no longer read server-error detail; the error `code` is still returned, which is what the Yatzy client and the admin page actually branch on. 4xx responses are deliberately not logged, so failed admin logins stay invisible - acceptable now that login is throttled, but worth revisiting if abuse appears. `api/_lib/http.js` grew from 31 to 71 lines and is now genuinely the shared HTTP contract for every endpoint. A malformed request body now produces the handler's own 400 instead of a 500.
Alternatives_Rejected: A logging library or an error-reporting service (Sentry) - rejected as far past "minimum", and a new dependency for a hub of party games. Threading a request id through every handler - rejected as duplicating what Vercel already provides. Adding `window.onerror` / `unhandledrejection` on the client - rejected deliberately: with no reporting endpoint to send to, the handler could only call `console.error`, which the browser already does for uncaught errors, so it would be pure ceremony. Worth adding only alongside a real sink.

## 2026-08-30 - Make CI a real gate: fix the ESLint globs, format only the maintained surface

Decision: Repointed `eslint.config.mjs` at the real tree (`public/**`, repo root, `shared/**`, plus a service-worker block and a `sourceType: "script"` block for `diceduel`), so `npm run lint` went from 1207 errors to 0 errors and 16 warnings. Added `.prettierignore` excluding build output, game content data, Markdown, and - deliberately - all of `public/games/**`. Added `endOfLine: "auto"` to `.prettierrc`. Ran `prettier --write` on what remains: 52 files, all of them the actively maintained surface (`api/`, `shared/`, `public/shared/`, `public/admin/`, the hub, the configs, the rules fragments). Switched CI from `npm install` to `npm ci`. `npm run check` now exits 0 end to end for the first time.
Context: Audit priority 4. CI ran lint, then `format:check`, then build, and had been red since it was written, so the build step had almost certainly never executed. Two root causes, both mis-diagnosed in the audit itself. First, the browser-globals block targeted `apps/**`, a directory that does not exist, leaving every game file with no globals: 1164 of the 1217 messages were phantom `no-undef` on `document` and `window`. Second, the audit blamed a quote mismatch, but measurement disproved it - switching to `singleQuote` changed the churn by less than 3% (18,584 lines versus 18,075). The code had simply never been run through Prettier. Separately, `core.autocrlf=true` with no `.gitattributes` means the Windows working tree is entirely CRLF, so Prettier's default `endOfLine: "lf"` flagged every line of every file locally, inflating the apparent damage.
Rationale: Formatting everything would have been 101 files and roughly 20,000 changed lines across 10 games that have no tests, burying every real diff. Formatting nothing would leave the gate red forever. The ratchet - ignore `public/games/**`, remove a game from the list the next time someone works on it - makes the gate real today for the code actually being changed, at zero risk, and shrinks the debt monotonically. Game content data (question banks, wordpacks) is excluded permanently: reformatting it produced ~500,000 changed lines for no readability gain. Markdown is excluded because `docs/DECISIONS.md` is append-only and Prettier's table realignment would rewrite past entries. `endOfLine: "auto"` fixes the tool on Windows without rewriting the tree, which `.gitattributes` plus `core.autocrlf=false` would have forced.
Consequences: `npm run check` is now a meaningful pre-push command and CI can be treated as blocking. `.prettierignore` is load-bearing and will look inconsistent until the games are swept - the ratchet comment in the file explains why. Lint still tolerates 16 warnings (dead code and unused `catch` bindings), so drift can accumulate as warnings; adding `--max-warnings 0` is the follow-up once that dead code is addressed. `public/games/yatsy/**` is ignored by Prettier even though Yatzy is actively developed, which is the one arguable exclusion: it is the largest single file in the repo (2077 lines, 2278 would change). Four real defects surfaced and were fixed in `public/games/millionaire/app.js`: two duplicate object keys, eight useless escapes, and a U+202F narrow no-break space inside a comment.
Alternatives_Rejected: Reformatting all 101 files in one dedicated commit - offered, and declined by the user in favour of the maintained-surface scope. Making `format:check` non-blocking or moving it after the build - rejected as a gate that reports nothing. Raising `printWidth` from 80 to 100 - measured (it would cut churn from 20,633 to 18,075 lines) but not applied, since changing a formatting convention is the user's call and the benefit disappears once the sweep is done. Adding `.gitattributes` with `* text=auto eol=lf` - the more canonical fix for the CRLF problem, but it renormalises the entire working tree on next checkout, which is far too invasive to mix with undeployed security work.

Decision: Replaced the 14-token `::root` block in `public/shared/css/base.css` with a `:root` block containing `--font-sans` only, and removed `color: var(--color-text)` from the `body` rule. The audit's stated fix - change `::root` to `:root` - was deliberately not applied as written.
Context: Audit priority 5. The block was spelled `::root`, which matches nothing, so all 14 design tokens had been inert since they were written. The values describe a dark theme (`--color-bg: #050816`, `--color-text: #e5e7eb`), but `body` in the same file paints a light beige radial gradient, so the design had clearly moved on without the tokens following. Six pages load `base.css`: the hub, `wordplayer.html`, `/admin`, Pictionary, Olé Mains and Pyramide.
Rationale: Measured in the browser before touching anything, by injecting the corrected `:root` block at runtime and reading computed styles. Applying the audit's fix verbatim would have set `body` colour to `rgb(229, 231, 235)` - light grey on beige - on the hub and on `wordplayer.html`, where 10 elements inherit the body colour; `/admin` and Pyramide were safe because they set their own colour. So the "one-character fix" was actively harmful. Of the 14 tokens, only `--font-sans` and `--color-text` had any live consumer at all, both inside `base.css` itself: `--color-accent`, `--radius-*`, `--shadow-soft` and friends are referenced only by `public/games/easyfrog/style.css`, which nothing loads (Easy Frog is an external game, `kind: "external"` in `hub-config.json`, only its thumbnail is used), while Dice Duel and Millionaire declare their own correctly-spelled `:root` and never load `base.css`. Keeping 12 tokens with no consumer would be speculative (YAGNI).
Consequences: `body` now resolves `font-family` to the intended system-ui stack instead of falling back to Times New Roman. Verified that this changes nothing visible today: only `body` itself and a `<script>` tag were inheriting the serif, since every visible element in `hub.css` sets its own font - so this closes a latent trap rather than fixing a visible bug. `body` no longer declares `color` at all, which leaves the black default exactly as it computed before. `base.css` went from 60 to 50 lines. Verified with `npm run check` green plus a browser pass on the hub and `wordplayer.html`.
Alternatives_Rejected: Fixing `:root` and re-pointing `--color-text` at a dark value to keep the token system alive - offered to the user and declined; it would preserve 12 tokens that nothing consumes. Fixing `:root` as the audit described - rejected on measurement, it breaks readability on two pages. Leaving the block untouched - rejected: dead code that looks live is worse than no code, and the next person to add an element without an explicit font would silently get a serif.
